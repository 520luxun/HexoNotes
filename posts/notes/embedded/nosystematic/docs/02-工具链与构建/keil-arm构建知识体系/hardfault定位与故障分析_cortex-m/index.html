HardFault 定位与故障分析（Cortex-M）#

验证状态 本章的栈帧布局与故障位域基于 ARM 文档与工程经验，尚未在真实板卡/探针上实测；关键数值请以实机行为为准。

定位 本文是相邻专题第 7 项「HardFault 定位」的正式版。目标不是罗列寄存器，而是给出一套可复现的定位流程：从 CFSR 判断故障类型 → 取栈帧 → 用 .map/反汇编落到源码行 → 归类根因。

1. HardFault 是“兜底”#

Cortex-M 有四类 fault：MemManage、BusFault、UsageFault、HardFault。前三个默认未使能，发生时全部升级为 HardFault，并在 HFSR.FORCED 置位。

调试期建议使能三个子 fault（写 SCB->SHCSR），这样能直接停在更精确的异常里：

2. 故障状态寄存器#

寄存器地址作用
CFSR0xE000ED28可配置故障状态（MMFSR + BFSR + UFSR）
HFSR0xE000ED2C硬故障状态
MMFAR0xE000ED34MemManage 出错地址
BFAR0xE000ED38BusFault 出错地址
DFSR0xE000ED30调试故障状态（一般不看）

2.1 CFSR 位域#

区段位名称含义
MMFSR0IACCVIOL取指访问违例（MPU/XN）
1DACCVIOL数据访问违例
3MUNSTKERR异常返回出栈失败
4MSTKERR异常入栈失败
5MLSPERR惰性 FP 保存失败
7MMARVALIDMMFAR 有效
BFSR8IBUSERR取指总线错误
9PRECISERR精确总线错误（地址已知）
10IMPRECISERR不精确总线错误（地址未知）
11UNSTKERR返回出栈总线错误
12STKERR入栈总线错误
13LSPERR惰性 FP 保存总线错误
15BFARVALIDBFAR 有效
UFSR16UNDEFINSTR未定义指令
17INVSTATE非法状态（Thumb 位错）
18INVPC非法 PC（EXC_RETURN 错）
19NOCP协处理器未使能（FPU 未开）
20STKOF栈溢出（M8-M 才有独立位）
24UNALIGNED非对齐访问
25DIVBYZERO除零（需 CCR.DIV_0_TRP）

CFSR 是写 1 清零；HFSR 同样。读之前先看清哪一位为 1，再对照上表。

2.2 HFSR 关键位#

位名称含义
1VECTTBL向量表读取失败（向量表地址/内容错）
30FORCED由其他 fault 升级而来
31DEBUGEVT调试事件触发

FORCED=1 说明“本来是别的 fault，但没使能”，应回头使能子 fault 再看 CFSR。

3. 取栈帧：MSP、PSP 与 FP 帧#

3.1 判断用哪个栈#

异常入口的 LR 是 EXC_RETURN：

值含义
0xFFFFFFF1返回 Handler 模式，使用 MSP
0xFFFFFFF9返回 Thread 模式，使用 MSP
0xFFFFFFFD返回 Thread 模式，使用 PSP

判据：bit2 = 1 → PSP，bit2 = 0 → MSP。

3.2 栈帧布局#

偏移内容
+0x00R0
+0x04R1
+0x08R2
+0x0CR3
+0x10R12
+0x14LR（返回地址）
+0x18PC（出错指令）
+0x1CxPSR

3.3 带 FP 的扩展帧（关键坑）#

若 EXC_RETURN 的 bit4 = 0，硬件压入的是 0x68 字节扩展帧：

SP 指向 S0，不是 R0。直接把 SP 当 R0 打印，会把 S0 当第一个参数、整体错位 0x48 —— 这是自制 HardFault handler 最常见的 bug。

图：基本帧（bit4=1，0x20）与 FP 扩展帧（bit4=0，0x68）；扩展帧 SP 指向 S0，R0 在 SP+0x48。

只有 bit4=1（无 FP 帧）时，SP 才直接指向 R0。

6. 十类典型案例#

#现象关键位根因处理
1写空指针DACCVIOL + MMARVALID，MMFAR=0未判空加判空；MPU 保护 0 地址
2野指针写PRECISERR + BFARVALID指针越界/已释放查 BFAR 地址归属
3函数指针错INVSTATE（bit0=0）或 IBUSERR跳到非 Thumb 地址/空指针校验函数指针
4栈溢出STKERR / IMPRECISERR，SP 越界局部数组过大/递归增大栈；8.9 静态分析 + 水位
5FPU 未使能NOCP用了浮点但 CPACR 未开启动时置 CP10/CP11
6除零DIVBYZERO未判分母判零；或开 CCR.DIV_0_TRP 便于发现
7非对齐访问UNALIGNED强转指针/packed 结构体；M0 直接 fault，M3/M4 需开 CCR.UNALIGN_TRP 才触发用 memcpy 或对齐访问
8跳到 RAM 空区IBUSERR未初始化函数指针初始化/断言
9向量表错VECTTBLVTOR 未设/向量表被覆盖检查 scatter 与 VTOR
10异常返回崩溃INVPC手工改 LR/EXC_RETURN不要伪造 EXC_RETURN

非对齐访问在 Cortex-M0/M0+ 上必然 fault；M3/M4/M7 默认允许（硬件拆分访问），只有置位 CCR.UNALIGN_TRP 才会进 fault，便于调试期发现。

即便在 M3/M4/M7 上，默认允许的也只是普通单寄存器 LDR/STR；LDM/STM 多寄存器、LDREX/STREX 独占访问、以及 SP 相关指令遇到非对齐地址仍会产生 fault（与 UNALIGN_TRP 无关）。

6.1 IMPRECISERR（不精确总线错误）怎么查#

写缓冲导致错误地址无法回填，BFAR 无效：

  1. 临时关闭写缓冲（SCB->ACTLR 或 MPU 配置），让错误变精确；
  2. 或二分注释代码，缩小触发范围；
  3. 检查外设时钟是否使能（访问未开时钟的外设常表现为总线错误）。

7. Keil 实操#

面板用途
Registers → Banked看 MSP/PSP、LR（EXC_RETURN）
Peripherals → Core Peripherals → SCB直接看 CFSR/HFSR/MMFAR/BFAR
Call Stack + Locals栈帧未损坏时可回溯调用链
Disassembly用 PC 定位出错指令
Memory按 BFAR/MMFAR 查看地址内容
Watch观察关键变量是否被踩

实操顺序：停住 → 读 CFSR → 读 LR 判断栈 → 读 PC → 反汇编 → 查 map。

8. 防御性设计#

手段作用
MPU guard 区栈/堆边界外设只读或不可访问，越界立刻 fault 而非静默踩内存
栈水位（0xCD 填充）量化实际栈用量（8.9）
断言 + 参数校验把“野指针”挡在 fault 之前
函数指针表初始化未注册的回调置为默认空实现
noinit 故障记录复位后仍能读到上次 fault 现场
看门狗 + 故障复位现场无法恢复时保证系统自愈
