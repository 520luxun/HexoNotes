WSL2 与 Ubuntu 完全使用指南#

Windows 上跑 Linux 的两条路线：一条命令的 WSL2，或一台完整的 VMware 虚拟机。

本文定位 把 Windows 上跑 Linux 的两条主流路线讲透：WSL2（微软原生，一条命令装好，秒开）与 VMware 虚拟机（完整独立系统，USB/内核实验不可替代）。 主线是 WSL2 的完整落地流程 —— 从 BIOS 开虚拟化到迁移到 D 盘；副线是 VMware 的安装与 14 维对比，最后给选型结论和排错手册。

前置条件BIOS 开 SVM / VT-x + 两个 Windows 组件（子系统 + 虚拟机平台）
必开项/etc/wsl.conf 写 systemd=true，否则 systemctl 全部报错

🧠 1. 概念：WSL 到底是什么#

1.1 一句话定义#

WSL（Windows Subsystem for Linux，适用于 Linux 的 Windows 子系统）= Windows 内置的一台”轻量 Linux 引擎”。

你在 Windows 里直接打开一个真正的 Ubuntu 终端，用 apt、gcc、python3、git，不需要装虚拟机软件，也不需要重启进双系统。

它能做的事：

  • 在 Windows 里打开真正的 Ubuntu 终端，跑 Linux 工具链；
  • 编译 Linux 下的项目（C/C++、OpenHarmony、STM32 交叉编译、嵌入式工具链）；
  • 跑 Docker（配合 Docker Desktop 的 WSL2 后端）；
  • 运行 Linux 图形程序（WSLg，窗口直接显示在 Windows 桌面上）；
  • 与 Windows 文件系统双向访问，代码放哪边都能读写。

1.2 WSL1 与 WSL2：两代完全不同的方案#

WSL1WSL2
原理系统调用翻译层（lxss 驱动）轻量虚拟机 + 真正的 Linux 内核
内核没有独立内核微软定制 Linux 内核（5.15 / 6.6 LTS）
兼容性部分系统调用不支持（Docker 等跑不了）完整兼容
文件系统直接读写 NTFS，跨盘 IO 快ext4 虚拟磁盘，跨盘走 9P（慢）
启动极快快（秒级）
现状已淘汰当前默认

记住结论 新装系统默认就是 WSL2。wsl -l -v 里 VERSION 列必须是 2 —— 如果是 1，编译速度、Docker、兼容性都会打折。

1.3 架构原理（两张图看懂）#

WSL2 本质是一台轻量虚拟机，但和你平时用的 VMware 不同：

  • 共享内核：所有 WSL2 发行版共用同一个微软定制内核，不会每装一个发行版就起一套系统；
  • 按需启动：打开终端才启动，关掉后自动释放资源，闲置时几乎不占内存；
  • 深度集成：文件系统、网络、图形界面都通过微软的特殊机制与 Windows 打通，不是孤立的虚拟机。

每个 WSL2 用户都会遇到的前提 WSL2 需要 CPU 虚拟化（Intel VT-x / AMD-V）+「虚拟机平台」组件。这就是第 2 章要做的事；报错 0x80370114 基本都是这两项没做好。

1.4 三种”在 Windows 上跑 Linux”的方式#

方式本质启动硬件访问适合
WSL2轻量虚拟机 + 深度集成1~2 秒受限（需 usbipd）日常开发、编译、服务
VMware完整独立虚拟机30 秒 ~ 数分钟较好（一键 USB 直通）驱动实验、硬件调试
双系统真机原生安装需重启切换完全原生重度 Linux 用户

🧰 2. 安装前的准备#

准备工作只有三件事：硬件达标、BIOS 开虚拟化、Windows 开两个组件。做扎实了，安装就是一条命令。

2.1 硬件与系统要求#

项目要求说明
CPU支持虚拟化（Intel VT-x / AMD-V，即 SVM）近十年的 CPU 基本都支持
内存4 GB 起，建议 8 GB+WSL2 默认最多用 50% 物理内存
系统Windows 10 版本 2004+（内部版本 19041+）或 Windows 11winver 可查
Windows 功能「适用于 Linux 的 Windows 子系统」+「虚拟机平台」见 2.3
BIOSSVM Mode（AMD）/ VT-x（Intel）= Enabled见 2.2

Windows 家庭版也行 WSL2 不需要专业版，也不需要启用 Hyper-V 功能。「虚拟机平台」是独立组件，家庭版同样具备。

2.2 BIOS 开启虚拟化（SVM / VT-x）#

  1. 重启电脑，开机时按进 BIOS 的键 常见：联想/小新 F2（或 Fn+F2）、戴尔 F2、惠普 F10、微星 Del、华硕 F2/Del。开机 LOGO 出现时连续敲击。

  2. 找到虚拟化选项 通常在 Advanced / Configuration / CPU Configuration 下：

    • AMD 平台叫 SVM Mode（Secure Virtual Machine）；
    • Intel 平台叫 VT-x / Virtualization Technology；
    • 中文 BIOS 里叫「虚拟化技术」或「AMD 虚拟化」；
    • 部分机型藏在「安全 / Security」菜单里。

  3. 设为 Enabled，用 F5/F6 或方向键调整。

  4. 保存退出：F10 → Save & Exit → 回车，电脑自动重启。

最常见的一类失败 Windows 组件全开了还是报 0x80370114，几乎都是 BIOS 里的 SVM 没开。先按 2.4 验证，别急着重装系统。

4.2 /etc/wsl.conf 全解（Linux 侧配置）#

段常用项说明
[boot]systemd是否启动 systemd
[automount]options=metadata让 /mnt/c 支持 Linux 权限位（Windows 文件需要）
[network]hostname、generateResolvConf主机名、DNS 生成
[interop]appendWindowsPath关掉可避免 PATH 里混入 Windows 程序
[user]default默认用户（wsl --import 后必配）

改配置的通用套路 改 /etc/wsl.conf 后必须 wsl --shutdown 再进才生效；改 .wslconfig 同理。两者一个在 Linux 侧、一个在 Windows 侧，别搞混（见 4.3）。

4.3 .wslconfig 全解（Windows 侧配置）#

位置：C:\Users\你的用户名\.wslconfig（用记事本创建）。

配置项作用
memory内存上限，如 8GB、16GB。不要分给全部内存，Windows 自己也要用
processors可用 CPU 核心数
swap / swapFile交换分区大小与位置，编译大工程时有用
localhostForwarding端口转发，让 Windows 用 localhost:端口 访问 WSL 服务
networkingMode=mirrored镜像网络模式，见第 8 章
dnsTunnelingDNS 走 Windows 隧道，解决”能 ping IP 不能 ping 域名”
autoMemoryReclaimgradual / dropcache / disabled，回收闲置内存
sparseVhd虚拟磁盘稀疏化，wsl --manage <发行版> --set-sparse true 也可单独设
kernel自定义内核路径（一般用不到）

两个必须记住的点

  1. 改完 .wslconfig 必须 wsl --shutdown 才生效；
  2. WSL2 默认最多占物理内存的 50%（旧版本上限 8GB），内存小又常编译的机器，把 memory 调大、同时开 autoMemoryReclaim。

6.3 性能与安全红线（嵌入式开发尤其注意）#

两条硬规则 ① 项目代码放 Linux 侧。 在 WSL 里编译项目（内核模块、OpenHarmony、大型 C 工程）时，代码应放在 /home/用户名/ 下。跨盘（/mnt/f）读写走 9P 协议，大量小文件 IO 会慢 5～10 倍，编译大型工程尤其明显。 ② 不要在 Windows 里直接编辑 Linux 侧文件。 用资源管理器 \\wsl$ 直接改 ext4 里的文件，容易搞乱权限位（还可能混进行尾差异），导致编译报错。Linux 代码在 Ubuntu 内编辑，Windows 文件放 /mnt/。

权限问题的补救办法：如果确实需要在 /mnt/c 上执行 chmod/chown，给 /etc/wsl.conf 的 [automount] 加 options="metadata"，然后 wsl --shutdown 重启。

🖥️ 7. WSLg 图形界面#

7.2 常用图形程序#

WSLg 还支持：剪贴板互通、声音输出（Wayland）、多窗口。

7.3 与 Windows 侧工具配合（以 AMD Privacy View 为例）#

WSLg 的图形窗口本质上是 Windows 桌面上的普通窗口，因此所有作用于 Windows 窗口的工具都对它生效：

  • 眼动防窥（AMD Privacy View）：Windows 侧开启并完成校准后，Ubuntu 的图形窗口同样会被模糊/清晰化，视线聚焦处清晰、其余模糊；
  • 注意：这类工具会占用 GPU 资源，跑大型编译或 GPU 计算时建议先关掉。

提示 这条对任何”屏幕级”工具都成立（录屏、护眼滤镜、防窥）。反之，纯 Linux 侧的窗口管理行为（如某个 GTK 主题）不会影响 Windows 的其他窗口。

🌐 8. 网络模式#

8.1 默认 NAT 模式#

WSL2 默认使用 NAT：Ubuntu 有自己独立的虚拟网卡和 IP。

特点：

  • Ubuntu 里启动 Web 服务（如 python3 -m http.server），Windows 浏览器直接访问 localhost:端口 即可（靠 localhostForwarding）；
  • Windows 与 Ubuntu 互相访问用 localhost，不用记 IP；
  • Ubuntu 的 IP 每次重启可能变化（ip addr 查看）。

8.2 镜像网络模式（mirrored）#

Win11 22H2+ 支持 networkingMode=mirrored：WSL 与 Windows 共享网络栈，IPv6、防火墙规则一致，局域网设备可以直接访问 WSL 里的服务。

适合：需要把 WSL 里的服务暴露给手机/同事电脑，或 IPv6 环境。

💾 11. 把 Ubuntu 迁移到 D 盘#

WSL 默认把发行版装在 C 盘（C:\Users\用户名\AppData\Local\Packages\...）。C 盘紧张时，用「导出镜像 → 卸载 → 导入到 D 盘」三步把整个系统搬走，配置和已装软件全部保留。

11.1 迁移原理#

顺序不可颠倒 必须先 export 成功，再 unregister。 unregister 会删除 C 盘里的全部数据，且不可恢复。导出后先确认 .tar 文件存在且大小正常（几个 GB），再执行下一步。

11.2 完整操作（管理员 PowerShell）#

Step 1 · 准备目录、确认发行版名

记下 NAME 列的名字（通常就是 Ubuntu），后面命令用它替换。

Step 2 · 关闭正在运行的发行版

不终止的话，导出时文件被占用，会失败或得到损坏镜像。

Step 3 · 导出镜像

等待完成，D:\WSL\Ubuntu.tar 会有几个 GB。确认文件大小正常再做下一步。

Step 4 · 卸载 C 盘上的临时安装

这一步释放 C 盘空间，Ubuntu 从 WSL 列表消失。

Step 5 · 导入到 D 盘

参数依次是：发行版名 + 存放目录 + 镜像文件 + WSL 版本。D:\WSL 下会生成 ext4.vhdx 虚拟磁盘，Ubuntu 从此不占 C 盘。

Step 6 · 配置默认用户（导入后默认是 root）

之后从开始菜单或 wsl 进入，默认登录你的普通用户，之前装的软件、配置、家目录文件都还在。

11.3 注意事项#

注意事项说明
export 前必须 terminate不终止进程，导出会因占用失败或镜像损坏
先确认 export 成功再 unregister检查 .tar 大小（几个 GB 为正常），卸载不可逆
路径避免中文与空格D:\WSL 这类纯英文路径最稳
wsl.conf 用追加而非覆盖用 >>，别用 >，否则会覆盖 [boot] systemd=true
导入后默认 root 登录必须创建普通用户并写 [user] default=
迁移后路径不变\\wsl$\Ubuntu、/mnt/c 等访问方式照旧
镜像体积装得越多 tar 越大；迁移验证无误后可删掉 tar

14.1 演进时间轴#

时间事件说明
2016WSL 初代（后称 WSL1）随 Win10 周年更新推出，目标是”让 Linux 二进制直接跑在 Windows 上”，采用系统调用翻译层

14.2 关键差异表#

维度WSL1WSL2
架构系统调用翻译层（lxss 驱动）轻量虚拟机 + 真正 Linux 内核
内核无独立内核微软定制内核（5.15 / 6.6 LTS）
系统调用兼容性部分不支持（Docker 等依赖完整内核的功能跑不了）完整兼容，Docker 直接跑
文件系统直接读写 NTFS，跨盘 IO 快ext4 虚拟磁盘（Linux 侧快），跨盘走 9P（慢）
启动速度极快（无虚拟机）快（秒级）
内存管理与 Windows 共享独立内存空间（可设上限）
网络与 Windows 共享网络栈独立虚拟网卡（NAT / mirrored）
IO 密集型任务（编译）表现差Linux 侧接近原生，编译显著提升
现状几乎淘汰当前默认，微软主推

为什么 WSL2 编译更快 WSL1 的文件操作要翻译成 Windows 调用，还要走完整 NTFS 权限检查；WSL2 直接操作 ext4，配合完整内核，编译大型工程（Linux、OpenHarmony）性能接近物理机 —— 这是嵌入式开发者首选 WSL2 的核心原因。

WSL2 的代价 需要 CPU 虚拟化 + 虚拟机平台；跨 Windows 盘（/mnt/c）读文件反而比 WSL1 慢。所以：代码放 Linux 侧，别放 /mnt。

⚠️ 17. 常见误区#

误区事实
”WSL 就是个虚拟机”是轻量虚拟机 + 深度集成（文件/网络/图形/剪贴板），不是传统隔离虚拟机
”WSL1 比 WSL2 快”只对跨盘文件 IO 成立；编译、Docker、整体兼容性 WSL2 完胜
”WSL 里能直接插 U 盘”不能，要 usbipd 附加；要稳定 USB 用 VMware
”WSL 能编译加载内核模块”不能 insmod 自定义模块（定制内核无 headers）；用 VMware / QEMU
”装了 VMware 就不能用 WSL”新版可共存（都基于虚拟化平台），仅性能略有折损
”WSL2 需要 Hyper-V”只需要「虚拟机平台」组件，不需要勾选 Hyper-V
”家庭版不能装 WSL”Win10/11 家庭版完全支持 WSL2（前提是 BIOS 虚拟化已开）
“代码放 Windows 盘编译没问题”跨盘编译大型工程慢 5~10 倍，代码要放 Linux 侧
”改完 .wslconfig 立刻生效”必须 wsl --shutdown
”wsl --unregister 只是删除快捷方式”它会删除全部数据，不可恢复

进入 Ubuntuwsl 或开始菜单点 Ubuntu
查看所有发行版wsl -l -v
查看 WSL 版本wsl --version
更新 WSLwsl --update（管理员）
设为 WSL2wsl --set-default-version 2
关闭 WSL 释放资源wsl --shutdown
关闭单个发行版wsl --terminate Ubuntu
重置密码wsl -d Ubuntu -u root → passwd 用户名
备份发行版wsl --export Ubuntu D:\backup\ubuntu.tar
恢复发行版wsl --import Ubuntu D:\WSL D:\backup\ubuntu.tar --version 2
删除发行版wsl --unregister Ubuntu（不可恢复）
磁盘稀疏化wsl --manage Ubuntu --set-sparse true
