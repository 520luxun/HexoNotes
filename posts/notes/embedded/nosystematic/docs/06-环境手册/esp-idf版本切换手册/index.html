ESP-IDF 版本切换手册（ESP32-S3 · Routine 工程集）#

本机现状：D:\Espressif-5.1.6 与 D:\Espressif-6.0.2 两套完整环境同时存在，114 个工程里 113 个用 5.1.6、1 个（hello_world_6.0.2）用 6.0.2，全局默认仍是 5.1.6。 本文只讲一件事：怎么把”某个工程”或”整台机器”切到另一个 ESP-IDF 版本，以及切完怎么验证、出问题怎么退回。原理与安装/删除的完整 SOP 见工程内的 docs\ESP-IDF-维护手册.md（第 10、11、12、17 章）。

0. TL;DR（三分钟照做）#

命令行临时用 6.0.2（不影响 VS Code、不影响别的终端）：

切换前后各做一次体检：

一句话记住 切换 ≠ 卸载重装。 两个版本一直躺在硬盘上，切换只是改”这个工程用谁”的指针。改完删 build + 完全重启 VS Code，就是全部动作。

1. 先搞懂：到底是谁在决定”用哪个版本”#

ESP-IDF 工程编译时，扩展 / CMake 会按下面的优先级找版本，上面一层存在，下面就被忽略：

四个”开关”各自管什么：

#开关位置管什么什么时候要改
①工程级配置<工程>\.vscode\settings.json 的 idf.espIdfPathWin 等这个工程在 VS Code 里编译/烧录用哪个版本切某个工程（最常用）
②全局默认用户级环境变量 IDF_PATH / IDF_TOOLS_PATH / IDF_PYTHON_ENV_PATH新开的命令行、没写死配置的工程想让”命令行默认”也换
③进程缓存正在运行的 VS Code 进程② 改完后必须完全重启才读到新值每次切完都要做
④版本登记表D:\Espressif\eim-default\tools\eim_idf.json只决定插件 UI / EIM 列表里能看到哪些版本，不决定编译用哪个装/删版本后

第 ④ 项最容易误解 登记表（eim_idf.json）里有 5.1.6 和 6.0.2，只代表”界面里能选”。工程真正用哪个，看的是它自己的 settings.json；命令行真正用哪个，看的是当前终端的环境变量。三者是独立的。

补充两条本机事实：

  • VS Code 用户设置里没有全局 idf.espIdfPath，只有 idf.eimIdfJsonPath（指向上面那份登记表）和 idf.gitPathWin（5.1.6 自带的 git）。所以本机实际上是”工程级绝对路径说了算”，改环境变量不会意外影响已配置的工程。
  • 6.0.2 没有自带 idf-git，扩展会用系统 Git：D:\Git\Git\cmd\git.exe。

4. 方法 A（推荐）：只切一个工程#

适用： 工程 A 用 5.1.6、工程 B 用 6.0.2 混着用；不想动全局默认。

4.1 先预览（不写任何文件）#

会打印：目标源码目录、Python、工具 PATH 条目数、cmake/git 路径，以及将要写入的完整 JSON，最后提示 DryRun 模式：未更新用户环境变量。看清路径无误再正式执行。

4.2 正式切换#

成功时依次出现：

4.3 它到底改了什么、没改什么#

会写（工程 settings.json）：

键值
idf.espIdfPathWin目标版本源码目录
idf.pythonBinPathWin目标版本的 python.exe
idf.toolsPathWin目标版本的安装根
idf.customExtraPathsidf_tools.py export 输出的工具 PATH（cmake / ninja / 交叉编译器 / openocd / ccache …）
idf.customExtraVarsIDF_PYTHON_ENV_PATH、OPENOCD_SCRIPTS、ESP_ROM_ELF_DIR、IDF_CCACHE_ENABLE=1、PYTHONUTF8=1
idf.gitPathWin若该安装根下有 idf-git（5.1.6 有，6.0.2 没有 → 不写这项）
cmake.cmakePath / cmake.generator该版本的 cmake；Ninja
cmake.configureEnvironmentIDF_PATH / IDF_TOOLS_PATH

不会碰（工程个性化配置全部保留）： idf.portWin（串口）、idf.adapterTargetName、idf.flashType、idf.openOcdConfigs、C_Cpp.*（IntelliSense）、files.*。

也不会做的事： 不安装/卸载版本；不改 sdkconfig 和 main/；不删 build（要你手动删）；不加 -KeepEnv 时不改环境变量之外，其它一律不动。

为什么 customExtraPaths 不能手抄 两版本的工具版本、目录名、条目数都不同（5.1.6 共 16 条，6.0.2 共 12 条，且 6.x 编译器改名为 xtensa-esp-elf）。脚本每次都实时问 idf_tools.py export，所以永远是对的；手抄旧模板会踩”找不到编译器”。

4.4 切换后必做三步（漏一步就可能白切）#

为什么必须”完全退出” Reload Window 只重建渲染进程，扩展宿主进程可能还活着，仍拿着旧版本路径。本机历史上多次出现”改了配置、Reload 后仍按旧版本编译”，全部靠 File → Exit 解决。

11. 回滚#

切换是”改指针”，所以回滚也是改指针，不用重装：

用备份恢复（脚本每次写入前都会留 .bak-时间戳）：

12. 增 / 删版本（简版）#

完整 SOP 见 docs\ESP-IDF-维护手册.md 第 17 章。

新增一个版本（例如 5.4）：

  1. 装到独立目录 D:\Espressif-5.4（不要覆盖旧目录，venv 里是绝对路径）。
  2. 进源码目录执行 export.ps1，确认 idf.py --version（5.x 布局是 D:\Espressif-5.4\frameworks\esp-idf-v5.4，6.x 是 D:\Espressif-6.0.2\v6.x\esp-idf，先 Get-ChildItem 看清目录名）。
  3. 生成模板：.\tools\switch-idf-version.ps1 -EspressifRoot D:\Espressif-5.4 -TemplateOut .\templates\settings.esp-idf-5.4.json
  4. 用方法 A 把工程切过去 → idf-versions.ps1 复核。
  5. 让 UI 也能看到：用 EIM 安装会自动登记；离线安装则需手工写 eim_idf.json（无 BOM）或 eim import。

删除一个版本：

四条铁律：

  1. 裸跑 idf.py build 前先 export.ps1。
  2. 含中文的 .ps1 / .md 用 UTF-8 with BOM；给程序解析的 .json（登记表）无 BOM。
  3. 删 C:\Espressif 只能用 cmd /c rmdir "C:\Espressif"；不要 Remove-Item -Recurse（会跟随目录联接删掉 D 盘真实数据）。
  4. 删版本前必须先体检、切走引用、删 build。

14. FAQ#

Q1：切到 6.0.2 后，5.1.6 会被删或坏掉吗？ 不会。两套安装完全独立，切换只改配置指针。想回去随时切。

Q2：切换要重新安装、要联网吗？ 不要。秒级完成，只写 settings.json（可选的全局环境变量），不下载任何东西。

Q3：同一个 VS Code 窗口开两个不同版本的工程行吗？ 技术上可以（每个工程看自己的 settings.json），但扩展的版本状态是按窗口/工作区维护的，混开容易互相串。稳妥做法：一个工程一个窗口，或一次只编译一个。

Q4：为什么我改了 settings.json，编译还是旧版本？ 按顺序查：① build 删了吗 ② VS Code 完全退出了吗 ③ 改的是不是这个工程的 .vscode\settings.json ④ idf-versions.ps1 的归属对不对 ⑤ 是不是 CMakeCache.txt 残留。

Q5：UI 里选版本和脚本切，哪个优先？ 工程 settings.json 里写死的绝对路径优先。UI 一般改用户/全局设置，所以本机建议”脚本切工程、UI 只看”。

Q6：30_music 能切到 6.0.2 吗？ 配置能切，编译不行：它用旧 I2S API，6.0 已移除 driver/i2s.h。要上 6.0 必须先迁移到 i2s_std.h。验证 6.0.2 请用 hello_world_6.0.2。

Q7：只切命令行会影响 VS Code 吗？ 不会。export.ps1 只改当前终端进程；VS Code 按工程配置走，二者互不干扰。

Q8：怎么知道某版本还能不能删？ idf-versions.ps1 的”结论”段：引用数 = 0 且无失效引用，才可删。删前仍要把工程切走、删 build。

Q9：脚本的备份在哪、会不会越积越多？ 在 settings.json 同目录，命名 settings.json.bak-yyyyMMdd-HHmmss。确认稳定后可清理。
