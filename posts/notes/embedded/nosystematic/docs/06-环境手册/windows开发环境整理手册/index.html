Windows 开发环境整理手册#

现状：本机装过 4 个 Python、2 套 C++ 工具链、84 条 PATH 条目，其中混有失效项、重复项与指向已删目录的 IDE 配置；C 盘还意外多出一个 Python 3.15.2。 本次结果：4 个 Python 全部归位 D 盘、PATH 84 → 59、3 处 IDE 断链修复、2018 年的 MinGW 8.1.0（436.6 MB）由 MSYS2 GCC 16.1.0 替代。

TL;DR#

遇到什么看第几节

怎么给整台机器做一次”谁在用”体检§8

适用前提：Windows 10 及以上；采用”所有开发工具放 D 盘”的布局；使用 CLion / VSCode / PyCharm / WebStorm 中的若干。

5.3 迁移后工具链#

6. MSYS2 结构说明：ucrt64 / mingw64 / usr#

MSYS2 本质是多个互不兼容的”环境前缀”共存：

前缀性质CRT核心运行库
usr/MSYS 的 POSIX 模拟层（bash、pacman、coreutils）msysmsys-2.0.dll
ucrt64/原生 Windows + GCCUCRT（ucrtbase.dll，Win10+）libstdc++-6.dll 等
mingw64/原生 Windows + GCCMSVCRT（msvcrt.dll，极老）同名 DLL，但另一份二进制
clang64/原生 Windows + ClangUCRT另一份

为什么不能混用：libstdc++-6.dll、libgcc_s_seh-1.dll、libwinpthread-1.dll 在两套环境里同名而不同内容。若 PATH 同时含两套 bin 且顺序不当，进程会加载错 ABI 的 DLL → 崩溃或诡异乱码。MSYS2 的规矩是一个进程只用一套前缀，包名也区分：

本机实测：

补充：D:\MSYS2\mingw64\bin 仍留在 PATH（机器级第 44 位，空目录）。建议移除，避免今后误装 mingw-w64-x86_64-* 时埋下 DLL 冲突。

7. 为什么要保留 4 个 Python#

这是本次最容易被误解的部分——不是”没整理干净”，而是四个版本各自被锁死：

版本路径谁在依赖不可替换的原因
3.15.2D:\Python315终端默认、用户级 12 包（docx/pptx/lxml/PIL/XlsxWriter）最新版，日常入口
3.14.8D:\Python314用户级 64 包（numpy/scipy/pandas/matplotlib/pymupdf/openpyxl/pulp/yt_dlp）数据处理 + PDF 工具链
3.12.10D:\Python安装目录 174 包 / 1.5 GB（nncase / K210 / K510、cv2、onnxruntime）_nncase.cp312-win_amd64.pyd 只能 3.12 加载
3.9.13D:\Python39DevEco deveco-venv项目固定 cp39 二进制（PyNaCl 1.5.0 / aiohttp 3.8.5 / cffi 1.15.1）

四条硬约束：

  1. 二进制 ABI：.pyd 为特定 CPython ABI 编译，换版本即 ImportError。
  2. 上游支持窗口：nncase（嘉楠 K210/K510）只到 3.12；ESP-IDF 自带 3.11 环境且由 EIM 精确管理。
  3. 厂商工具链自治：DevEco、ESP-IDF 都不接受你替换它们的解释器。
  4. 全局包冲突：1.5 GB / 174 个包（含 numpy/pandas/scipy）若与另一套版本混装，必然打架。

正确的”统一”是统一入口，不是统一解释器 一个 base（3.15）+ 每个项目一个 venv，才是可持续方案。

8. 环境扫描：方法、口径与局限#

8.1 方法#

自写 Python 扫描器（D:\DevEnv\_audit\scan.py + analyze*.py）：

  1. 遍历 D:\ 全盘 + 用户配置目录（AppData/JetBrains/VSCode/Cursor/Documents/Desktop）
  2. 筛出配置类文件：.json/.xml/.iml/.cmake/.bat/.ps1/.toml/.ini/.cfg/CMakeCache.txt/CMakePresets.json 等
  3. 正则抽取所有绝对路径（[A-Z]:\\...），归一化去重
  4. 逐条 os.path.exists() 判定 + 记录引用它的文件与最新时间
  5. 另做一轮”活跃度扫描”：每个顶层目录近 30/180 天被修改的文件数
  6. 合并 PATH 全量、已安装软件（374 条）、运行进程、服务

8.2 规模#

完整报告：D:\DevEnv\_audit\环境资产扫描报告.md

8.3 局限性（必须知道）#

  • “配置里零引用” ≠ 没用：通过 PATH、环境变量、图形界面启动的程序不会被扫到（VMware、Keil、DevEcoStudio 都属于此类，只能靠活跃度判断）。
  • 日志/笔记里的历史路径是噪声：原始抽出 1,257 条，其中 E:\=、p:\module、C:\dir1 之类来自 CMake 模块模板、插件 README、构建日志，已剔除。
  • 未覆盖：注册表内部配置、数据库内部配置。

11. 常见问题速查#

报错 / 现象原因处理
