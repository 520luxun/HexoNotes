## 1. 一句话说清这是什么

一个**把 Obsidian 笔记自动发布成静态网站**的博客：本地跑一条命令，脚本把 Obsidian 库里的笔记复制、转换、压缩图片，Astro 生成静态页面，推到 GitHub 后由 Cloudflare Pages / GitHub Pages 自动上线。

```
D:\ObsidianFirstNotes\        ← 你的 Obsidian 库（唯一内容来源，脚本只读）
        │
        │  pnpm sync-notes   （scripts/sync-notes.mjs）
        ▼
src/content/posts/notes\      ← 生成副本（可随时整目录重建，不要手改）
        │
        │  astro build + pagefind
        ▼
dist\  →  git push  →  Cloudflare Pages / GitHub Pages / Gitee（镜像）
```

**核心心智模型**：`src/content/posts/notes/` 是**生成物**，不是源文件。改了会在下次同步时被覆盖。

## 3. 当前生效的规则（最终版）

这一节是**结论**，第 8 节记录这些结论是怎么试出来的。改规则前务必先读第 8 节，避免重复踩坑。

### 3.1 目录结构：完全照搬 Obsidian，不做任何重组

```
Obsidian 库                         →   网站
Embedded/PCB/Docs/1-1 xx.md         →   notes/Embedded/PCB/Docs/1-1_xx/index.md
Embedded/PCB/assets/Expand/...      →   notes/Embedded/PCB/assets/Expand/...
Embedded/FreeRTOS/01 xx.md          →   notes/Embedded/FreeRTOS/01_xx/index.md
```

- **层级不减、不改名、不挪动**
- 唯一的"改造"是：`文件名.md` → `文件名/index.md`（每篇笔记一个文件夹，见 3.2）

### 3.2 一篇笔记一个文件夹（图片隔离）

```
notes/Embedded/PCB/Docs/1-1_基础知识点1/
├── index.md                        ← 正文，图片引用 ./assets/xxx.png
└── assets/                         ← 只属于这篇笔记的图片
```

- 原因：早期所有图片共用一个 `notes/assets/` 目录，**两篇笔记里有同名图片（如都叫 `1.png`）时后者会覆盖前者，导致笔记显示别人的图**。分文件夹后彻底隔离。
- Stub：同一张图片被多篇笔记引用时会各存一份（1000 张图片 > 实际唯一图片数），换来的是零冲突。

### 3.3 分类 = 二级文件夹名，原样大小写

`makeCategory()`：取 `Embedded/<这里>/...` 这一层，**不翻译、不转换大小写**。所以侧边栏显示 `PCB 23`、`FreeRTOS 24`、`SchoolStudy 34`。

> `notes-sync.config.json` 里还留着 `categoryMap`（PCB→硬件电路 之类），但**已经没有任何代码引用它**，是遗留配置，可以删。

### 3.4 大小写：显示用 `path` 字段，不能用 URL 反推

- Astro 生成 slug 时会**强制转小写**，所以网址是 `/posts/notes/embedded/pcb/docs/...`
- 同步脚本会把库里的真实路径写进 frontmatter：`path: "Embedded/PCB/Docs"`
- 总目录页用 `post.data.path` 建树，所以显示的是 `Embedded / PCB / Docs`（库里原样），而不是小写
- 如果将来改了路径结构，`path` 会自动跟着变，不用手动维护

### 3.5 总目录页的呈现规则

`src/pages/catalog.astro`：

1. 层级树 = `path` 字段按 `/` 拆开（完整镜像文件夹结构，可无限层级）
2. **同一层里：先列文件夹，再列直接放在该层的文章**（README、索引、目录说明这类排在文件夹下面）
3. 文章按标题里的章节号排序（`1-1`、`1-2`…），没有编号的排在后面
4. 顶层默认展开，其余折叠；右上角有「全部展开 / 全部收起」
5. 每个分组后面显示 `N 篇`（含子层）

### 3.6 标签规范化（同步时自动压缩）

`scripts/sync-notes.mjs` 顶部两张表：

- `DROP_TAGS`：直接丢弃 —— `clippings`（Obsidian 剪藏器自动加的）、`文档索引`、`目录说明`
- `TAG_MERGE`：近义合并 —— 例如 `低通滤波/高通滤波/LC滤波/RL滤波/RC滤波器/滤波 → 滤波器`；`LC谐振/RLC/Q值/阻尼 → 谐振`；`EMI/共模干扰/差模干扰/X电容/Y电容 → EMC`；`虚短虚断/输入失调电压/轨对轨/差分放大/比较器 → 运算放大器`；`稳压电源/线性稳压/开关电源/降压/升压/电荷泵/软启动/浪涌电流/防反接/恒流源 → 电源设计`

效果：标签从 **约 70 个压到 28 个**（当前累计使用约 76 次）。改完表后跑一次 `pnpm sync-notes` 生效。

### 3.7 发布范围（哪些笔记会出现在网站上）

- 扫描整个库里匹配 `**/*.md` 的文件
- 排除：`Clippings/`、`Daily/`、`Excalidraw/`、`node_modules`、`.obsidian`、`.venv`、`.` 开头目录，**以及 `Study/`**（明确要求不上网站）
- 正文少于 120 字符的丢弃（`minBodyChars`）
- 源文件 frontmatter 里 `publish: false` 或 `draft: true` 的不会发布

### 3.8 图片处理

- `![[xxx.png]]` 和 `![](xxx.png)` 都会解析到库里的真实文件
- **外链图片**（`http(s)://`）会下载到本地缓存后随站点发布 —— 起因是 CSDN 图片有防盗链，直链会在访客浏览器 403
- 超大图片（>1 亿像素 / 边长 >10000 / 动图多帧）会被 `sharp` 压到 4096 内，避免构建器 OOM
- 扩展名统一小写（`22.PNG` → `22.png`），避免 Linux 构建机找不到文件
- 找不到源文件的图片会**直接删掉**该 `![]()`，不留 403 的死图

### 3.9 站点外观

- **全站照片背景**：`public/background.jpg` + `src/styles/main.css` 里 `body::before`（图片层）/ `body::after`（半透明遮罩，亮色 `rgba(255,255,255,0.82)`、暗色 `rgba(0,0,0,0.7)`）
- 背景地址通过 `src/layouts/Layout.astro` 的 `--site-bg` 变量注入，用 `import.meta.env.BASE_URL` 拼接，所以 `/` 和 `/HexoNotes/` 两种部署路径都能正确加载
- 想换背景图：直接替换 `public/background.jpg` 即可；觉得太淡/太深就改 `main.css` 里那两个 alpha 值

## 5. 常用命令

```bash
pnpm install              # 首次
pnpm sync-notes           # 只同步笔记（不构建）
pnpm dev                  # 同步 + 本地开发服务器
pnpm build                # 同步 + 构建 + 搜索索引
pnpm preview              # 预览 dist（本地构建产物）
pnpm audit:site           # 站点质检
pnpm new-post <文件名>     # 在 src/content/posts/ 下新建独立文章（不经过 Obsidian 同步，像 MISC/ 那样用）
pnpm push:all             # 推 GitHub + Gitee（触发自动部署）
```

**日常就一句话**：写完笔记 → `pnpm push:all`。

构建另一个域名/根路径时：

```bash
pnpm build:domain         # site=https://blog.luxunacc.xyz/ base=/
```

> **注意**：本地的 `astro preview` 进程经常残留并返回 404，看线上效果请直接打开 Cloudflare 地址。

## 6. 自动化部署

- `.github/workflows/build.yml` / `deploy-pages.yml`：push 到 `main` 后构建并发布 GitHub Pages
- `.github/workflows/biome.yml`：push / PR 到 `main` 时跑 `biome ci ./src`（代码风格检查），只影响 CI 红叉，不阻断部署
- Cloudflare Pages：连 GitHub 仓库，push 后自动构建（`DEPLOY_BASE=/`，即根路径）
- `scripts/deploy-server.mjs`：可选手动部署到自己的 ECS（`DEPLOY_HOST=... pnpm deploy:server`），当前**不使用**
- 自定义域名 `blog.luxunacc.xyz` **未启用**：迁移 NS 会影响同一 DNS 区域下的比赛 API / 视频服务

## 7. 已知限制与坑

1. **网址全小写**：Astro 的 slug 生成规则决定的，`Embedded` 在网址里是 `embedded`。显示名靠 `path` 字段修正。若一定要网址保留大小写，需要自定义路由，属于较大改动。
2. **改目录 = 改网址**：任何层级/名字变动都会让旧链接 404。近期已经历过多次结构调整，分享出去的链接可能需要重发。
3. **Gitee 配额**：仓库已超 819MB（图片历史累积），目前只是警告；到 100% 会拒绝 push，届时可以放弃 Gitee 镜像或做历史瘦身（会改写提交哈希，需强推）。
4. **`src/content/posts/notes/` 不要手改**：下次 `pnpm sync-notes` 会删掉整个目录重建。
5. **图片同名**：靠"每篇笔记独立 assets 目录"解决，不要再改回共享目录。
6. **外链图片**：下载失败的会消失（脚本主动删除死图，而不是留 403）。缓存目录是根目录下的 `.notes-image-cache/`（约 98MB；可安全删除，只是下次同步要重新下载）。
7. **站点是公开的**：任何人访问网址都能看到全部笔记，且 `robots.txt` 允许搜索引擎收录（只屏蔽 `/_astro/`）。注意 `robots.txt` 由 `src/pages/robots.txt.ts` 动态生成，要改规则得改这个文件，**不要**在 `public/` 下新建同名文件。若需私有化：禁止抓取（仅防收录）或上 Cloudflare Access（真登录）。
8. **网页端编辑**：静态站点没有后台。想"在网页上改"需要接 Pages CMS / Decap CMS（Git 作为存储），目前**未接入**。

## 8. 规则是怎么演变来的（避免重复踩坑）

| 阶段 | 做法 | 结果 |
|---|---|---|
| 最初 | Hexo 迁移到 Fuwari；所有图片共用一个 `assets/` 目录，分类做中文映射（PCB→硬件电路） | 图片会串图；分类名是"改造过"的 |
| 试错 1 | 分类尝试扁平化 / 二级分组（基础知识点 + 扩展资料）来回改了 3 轮 | 最终定为扁平分类（一个笔记一个分类字段） |
| 试错 2 | 想让目录页体现"主题 vs 扩展"，先后尝试：A/B 目录重组、A 层直接列 1-1~1-7、`基础知识点` 提为顶层、`扩展资料` 改名 `扩展` | 均被撤回：**任何对目录的改造都会偏离 Obsidian** |
| 试错 3 | 英文名统一大写（EMBEDDED / PCB / DOCS） | 被撤回：**要按库里原始大小写** |
| 修复 | 图片改为每篇笔记一个文件夹 | 串图问题根治 |
| 最终 | 目录 100% 照搬 Obsidian；显示名用 `path` 字段保留原始大小写；目录页"文件夹在上、文件在下" | 当前状态 |

**教训（重要）**：
- 用户的内容组织方式以 Obsidian 为准，**不要自作主张重组目录或改名字**
- 需要"美化/分组"时，只能在**展示层**做（如目录页的排序、折叠），不能动文件结构
- 动大小写这类细节，先确认"是显示层还是路径层"，Astro 的 slug 会偷偷小写化

## 10. 出问题时的排查顺序

1. **页面没更新** → Cloudflare/GitHub Actions 是否构建完成（1-2 分钟）；然后 Ctrl+F5 强刷（站点用了 swup 预取缓存）
2. **某篇笔记没出现** → 检查 `publish/draft`、正文字符数是否 >120、是否被 `exclude` 规则命中
3. **图片不显示** → 看 `index.md` 里是不是 `./assets/xxx.png`，对应 `assets/` 里有没有这个文件；源头则检查库里 `![[xxx]]` 能否解析到唯一文件
4. **分类/目录页名字不对** → 看该篇 frontmatter 的 `category` 和 `path` 是否符合库结构（`path` 缺失会 fallback 到小写 slug）
5. **构建失败** → 大概率是 schema 与 frontmatter 不匹配（`src/content/config.ts`），或某张图片 `sharp` 处理失败；本地跑 `pnpm build` 看完整报错
