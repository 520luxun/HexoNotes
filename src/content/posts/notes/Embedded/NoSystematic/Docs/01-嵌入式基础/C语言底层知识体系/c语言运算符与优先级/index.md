## C语言运算符

在嵌入式C开发中，运算符是操作硬件寄存器和内存的直接工具。理解它们有助于写出更高效、更底层的代码。

下面是嵌入式开发中最常用的几类运算符：

### 1. 算术运算符
就是最基本的数学计算，在嵌入式里常用于数值转换。需要注意`/`和`%`的效率相对较低。

-   `+` `-` `*` `/` `%`（取余）
-   `++` `--`（自增/自减，常用于循环）

### 2. 关系运算符
用于比较大小，结果是**真（1）**或**假（0）**，主要用来控制程序的流程。

-   `>` `<` `>=` `<=` `==` `!=`

### 3. 逻辑运算符
用于连接多个条件，实现复杂的判断逻辑，结果也是真或假。

-   `&&`（与）、`||`（或）、`!`（非）

### 4. **位操作运算符**（嵌入式核心）
这是嵌入式开发最重要的部分，用于**直接操作寄存器的单个bit**，效率极高。

-   `&`（按位与）：常用于**清零**（与0）或**保留**某些位（与1）。
-   `|`（按位或）：常用于**置位**（或1）。
-   `^`（按位异或）：常用于**翻转**特定位（异或1）。
-   `~`（按位取反）：常用于配合`&`操作实现清零。
-   `<<` `>>`（左移/右移）：常用于快速实现乘除2的幂，或拼接数据。

```c
// 示例：假设要设置 GPIOA 端口的第3位输出高电平
// GPIOA->ODR 是一个32位寄存器
GPIOA->ODR |= (1 << 3);  // 将第3位置1，其他位保持不变
```

### 5. 赋值运算符
-   `=`：基础赋值
-   `+=` `-=` `*=` `/=` `&=` `|=` `<<=` `>>=`  ：复合赋值运算符，写法更简洁，有些编译器还能生成更高效的机器码

### 6. 特殊运算符
-   **`sizeof`**：用于获取变量或数据类型在内存中占用的字节数，对把握内存使用情况很有用。
-   **`? :`**（三目运算符）：简单的if-else替代品，让代码更简洁。
-   **`&` `*`**（地址与取值）：在嵌入式里用于直接访问指定内存地址，或操作指针。
-   **`->`**（箭头）：用于通过结构体指针访问成员，访问硬件寄存器结构体时很常见，如上文的`GPIOA->ODR`。

#### 嵌入式避坑指南
1.  **区分`&`和`&&`**：`&`是按位与，常用于操作寄存器；`&&`是逻辑与，用于条件判断。写错可能导致程序逻辑完全错误。
2.  **优先级**：在混合运算时，如果不确定优先级，**多加括号**总没错。
3.  **不要混淆`=`和`<mark>`**：在`if`判断里，常写的`if(a </mark> b)`如果误写为`if(a = b)`，程序逻辑就变了。很多现代编译器会对此给出警告。

## C语言运算符的优先级

C语言运算符的优先级决定了在表达式中，哪个运算符先被计算。当多个运算符出现在同一个表达式中时，优先级高的运算会先执行。如果优先级相同，则由**结合性**（左结合或右结合）决定顺序。

理解优先级对避免细微的bug至关重要，尤其是在嵌入式开发中，经常需要混合位操作、指针运算和逻辑判断。下面是一张完整的优先级表（从高到低），并附有常见陷阱解析。

---

### C语言运算符优先级表（从高到低）

| 优先级   | 运算符                                               | 名称或含义                                       | 结合方向    |
| ----- | ------------------------------------------------- | ------------------------------------------- | ------- |
| 1（最高） | `()` `[]` `->` `.`                                | 括号（函数调用）、数组下标、结构体/联合体成员访问（箭头和点号）            | 左到右     |
| 2     | `!` `~` `++` `--` `+` `-` `*` `&` `(类型)` `sizeof` | 单目运算符：逻辑非、按位取反、自增/减、正负号、解引用、取地址、强制类型转换、求字节数 | **右到左** |
| 3     | `*` `/` `%`                                       | 乘法、除法、取余                                    | 左到右     |
| 4     | `+` `-`                                           | 加法、减法                                       | 左到右     |
| 5     | `<<` `>>`                                         | 左移、右移                                       | 左到右     |

| 9     | `^`                                               | 按位异或                                        | 左到右     |
| 10    | `\|`                                              | 按位或                                         | 左到右     |
| 11    | `&&`                                              | 逻辑与                                         | 左到右     |
| 12    | `\|`                                              | 逻辑或                                         | 左到右     |
| 13    | `? :`                                             | 条件（三目）运算符                                   | **右到左** |
| 14    | `=` `+=` `-=` 等                                   | 赋值及复合赋值                                     | **右到左** |

#### 嵌入式开发中常见的优先级陷阱

##### 1. **`*p++` 究竟是先取内容还是先移动指针？**
- **规则**：后置自增 `++` 的优先级高于解引用 `*`。但它的结合性是自右向左，且 `p++` 本身返回的是 `p` 的旧值。
- 表达式 `*p++` 被解析为 `*(p++)`：先取出 `p` 指向的值，然后 `p` 自增指向下一个元素。
- 如果想先移动指针再取值，应使用 `*++p`（前置自增）。

##### 2. **位操作符与关系运算符混用**
```c
// 错误：判断 GPIO 的第2位和第3位是否都为1？
if (GPIO->IDR & (1<<2) && (1<<3)) { ... }
```
- 按位与 `&` 的优先级（8）低于关系运算符（6/7），但高于逻辑与 `&&`（11）。但这里 `(1<<3)` 是常量，整个表达式可能不是预期行为。实际上，上面的写法等于：
  `if ( (GPIO->IDR & (1<<2)) && (1<<3) )`，因为 `&&` 的优先级最低。
- 更常见的错误是忘记加括号：
  ```c
  if (GPIO->IDR & (1<<2) == 0)   // 错误！
  ```
  这里 `<mark>` 优先级高于 `&`，所以先比较 `(1<<2)</mark>0`，结果为0，再与 `GPIO->IDR` 按位与，永远为0。
- **正确写法**：`if ((GPIO->IDR & (1<<2)) == 0)`

##### 3. **赋值运算符与比较运算符混淆**
```c
if (a = b) { ... }   // 这实际上是先赋值，然后判断 a 是否为真（非零）
```
- 赋值 `=` 优先级较低（14），但上面的表达式因为 `=` 是赋值，整个 `a = b` 的结果就是赋值后的 `a`。这通常不是程序员想要的比较 `a == b`。

##### 4. **移位运算符优先级低于加减法**
```c
uint32_t val = 1 << 2 + 3;   // 结果是 1 << (2+3) = 32，而不是 (1<<2)+3 = 4+3 = 7
```
- 移位 `<< >>` 的优先级（5）低于加减法（4），所以 `2+3` 先算。

##### 5. **逗号运算符的优先级最低**
```c
int a = (1, 2, 3);   // a = 3，因为逗号表达式从左到右计算，最终结果是最后一个
int b = 1, 2, 3;     // 语法错误！因为赋值优先级高于逗号，这里被解析为 (int b = 1), 2, 3;
```

---

#### 最佳实践

1. **当不确定时，多加括号**。括号 `()` 优先级最高，可以明确指定运算顺序，也让代码更易读。
2. **记住几个关键点**：
   - 单目运算符（`! ~ ++ -- * & sizeof (type)`）的优先级仅次于括号，且是右结合。
   - 算术运算符 > 移位 > 关系 > 位逻辑 > 逻辑 > 条件 > 赋值 > 逗号。
   - 赋值运算符和条件运算符是右结合，其余大多是左结合。
3. **在嵌入式寄存器操作中，多用宏或内联函数来封装位操作**，避免直接写复杂的表达式。

## C语言运算符的运算速度优先级

在C语言中，**运算符的优先级**决定的是表达式中运算的**先后顺序**，而**运算速度**是指不同运算符执行时所耗费的CPU时间。**两者没有直接关系**：优先级高的运算不一定执行得快，优先级低的运算也不一定慢。但理解运算速度的差异，对于编写高效的嵌入式代码很有帮助。

下面从嵌入式开发的角度，梳理常见运算符的相对速度，并给出一些实用的优化建议。

---

### 一、运算符速度的直观对比（从快到慢）

不同运算符的底层实现依赖CPU指令集，速度差异很大。大致排序如下：

1.  **最快**：`!` `~` `&` `|` `^` `<<` `>>`（按位逻辑、移位）
    - 这些指令通常在一个CPU周期内完成，直接操作寄存器位，效率极高。
2.  **较快**：`+` `-` `*`（加法、减法、乘法）
    - 加减法非常快；乘法在多数现代MCU上也有硬件乘法器，但可能略慢于加减。
3.  **较慢**：`/` `%`（除法、取余）
    - 除法通常需要多个周期，甚至可能用软件模拟，是算术运算中最慢的。
4.  **特殊**：`&&` `||` `?:`（逻辑与、逻辑或、条件）
    - 这些运算符具有**短路特性**，并非一定会执行所有分支，速度取决于具体情况，但本身控制流开销很小。
5.  **指针与成员访问**：`[]` `*` `->` `.` 速度与内存访问模式相关，可能涉及缓存或总线等待。

> **注意**：以上速度是理论上的相对比较，实际受MCU架构、编译器优化、操作数类型等影响。

---

### 二、嵌入式开发中的常见优化技巧

利用速度快的运算符替代慢的运算符，是嵌入式性能优化的常用手段。

#### 1. 用移位代替乘除（2的幂）
- **慢**：`a = b * 8;` → 可能调用乘法指令。
- **快**：`a = b << 3;` → 左移3位，相当于乘以2³，单周期完成。
- 同理，除以2的幂可用右移：`a = b / 4;` → `a = b >> 2;`（注意右移对于有符号数的行为，需确保无符号或正数）。

#### 2. 用位运算代替取余（2的幂）
- 取余 `%` 很慢，如果除数是2的幂，可以用按位与替代：
    - `a = b % 16;` → `a = b & 0x0F;`（仅适用于无符号数或已知b≥0）。

#### 3. 用位掩码代替复杂的逻辑判断
- 检查某一位是否为1：`if ((reg & (1 << 3)) != 0)` 比用 `==` 比较整个寄存器更快。

#### 4. 利用短路特性避免不必要的计算
- `if (ptr != NULL && ptr->value > 10)`：如果 `ptr` 为 `NULL`，就不会执行 `ptr->value` 的访问，既安全又可能提速。

#### 5. 用自增/自减代替加减
- `i++` 和 `++i` 通常对应单条CPU指令，比 `i = i + 1` 更简洁且可能生成更优代码（不过现代编译器大多能优化）。

---

#### 三、优先级与速度的混淆案例

初学者容易将优先级和速度混为一谈，比如认为 `*` 比 `+` 快（因为优先级高），但实际上乘法和加法的速度差异是由硬件决定的，与优先级无关。优先级只决定谁先算，例如 `a + b * c` 中 `b * c` 先算，并不代表乘法比加法快。

---

#### 四、关于编译器优化

现代编译器（如GCC、ARMCC）在优化选项开启时，会自动将某些乘除法替换为移位（如果除数是常量且为2的幂）。但为了代码可读性，建议在明确需要性能的地方才手动优化。**“不要过早优化”**——先写清晰易懂的代码，再用性能分析工具找出瓶颈进行优化。

---

#### 五、总结

- **优先级**：规定运算顺序。
- **速度**：取决于硬件指令和编译器。
- **常用快操作**：位运算（`& | ^ ~ << >>`） > 加减 > 乘 > 除/取余。
- **优化建议**：在循环或中断等对时间敏感的代码中，优先使用快速运算符。
