# 图像与视频压缩

> **本文定位**
> 把「图像 / 视频为什么能压这么小」讲清楚：**图像格式 → 视频帧类型 → 色彩空间 → 3D**。
> 主线是两种冗余：**空间冗余**（DCT + 量化）与**时间冗余**（I/P/B 帧预测）。

> **章节速览**
> #一、图像格式 · #二、视频压缩 · #三、色彩空间：RGB 与 YUV · #四、3D 效果 · #总结

## 一、图像格式

### 1. PNG

- **无损压缩**，支持透明通道 **RGBA**（红、绿、蓝、透明度）。
- 压缩方式：行滤波 + DEFLATE（LZ77 + 哈夫曼），适合有大片同色区域的图。
- **适用场景**：图标、界面元素、需要透明背景的图片。

### 2. JPEG / JPG

- **24 位有损压缩**（真彩色），照片与网络图片的主力格式。
- 压缩流程：

| 步骤 | 做了什么 | 效果 |
|---|---|---|
| 1. 颜色空间转换 | RGB → YUV（亮度 + 色差） | 人眼对亮度更敏感，色度可以少存 |
| 2. 分块 + DCT | 8×8 像素块做离散余弦变换 | 空间域 → 频域，能量集中到低频 |
| 3. 量化 | 按人眼敏感度丢弃高频系数 | **有损的核心**，压缩率的主要来源 |
| 4. 熵编码 | 对量化后的系数做哈夫曼编码 | 无损再压一层 |

- 注：哈夫曼编码是**熵编码**，不是加密；它只负责把数据写得更紧凑。
- 扩展：支持渐进式传输（先模糊后清晰）。

### 3. BMP

- 位图，一般不压缩（或仅简单 RLE），体积大。
- **常见场景**：早期 Windows 位图、嵌入式裸机显示的帧缓存。

### 4. RGB

- 原始像素表示：每像素 3 通道 × 8 位 = **24 位**，无压缩，数据量极大。
- 它是「原材料」，JPEG / YUV 都是在它基础上做变换与压缩。

### 一张表对比

| 格式 | 压缩 | 透明 | 典型用途 |
|---|---|---|---|
| PNG | 无损 | ✅ RGBA | 图标、截图、需要透明的图 |
| JPEG | 有损（DCT + 量化 + 熵编码） | ❌ | 照片、网页大图 |
| BMP | 无 / RLE | ❌ | 裸机显示缓存、老式位图 |
| RGB | 无 | ❌ | 原始帧数据、算法输入 |

## 二、视频压缩

### 1. 为什么原始视频必须压缩

以 1920×1080、24 位色为例：

- 单帧：1920 × 1080 × 3 B ≈ **6.2 MB**
- 24 fps：≈ **149 MB/s**，一分钟约 **9 GB**
- 30 fps：≈ **187 MB/s**，一分钟约 **11 GB**

不压缩就无法存储和传输，因此视频编码的本质是**在可接受的画质损失下，把码率降一到两个数量级**。

### 2. 人眼的三个特性

- **帧率**：15 帧/秒已有连续感，20~25 帧/秒较流畅，60 帧以上提升有限（高帧率主要减少运动模糊）。
- **亮度更敏感**：所以 RGB 转 YUV 后，色度可以降采样。
- **高频不敏感**：所以 DCT 后可以大胆量化高频系数。

### 3. 帧类型：I / P / B

| 帧 | 名称 | 怎么编 | 特点 |
|---|---|---|---|
| **I 帧** | Intra（关键帧） | 独立编码，类似一张 JPEG | 可随机访问，体积最大 |
| **P 帧** | Predicted | 参考**前一帧**，只存运动矢量 + 残差 | 体积小 |
| **B 帧** | Bi-predicted | 参考**前后两帧** | 压缩率最高，编解码最复杂 |

典型序列：`I B B P B B P … I`，两个 I 帧之间称为一个 **GOP**。
GOP 越长压缩率越高，但随机访问与抗丢包的粒度越粗。

### 4. 压缩三板斧

1. **空间冗余**：帧内 DCT + 量化（I 帧、JPEG 同款）。
2. **时间冗余**：帧间运动估计与补偿，只传「变化的部分」（P/B 帧）。
3. **熵编码**：哈夫曼 / 算术编码 / CABAC，把符号压到接近信息熵。

### 5. 主流标准

| 标准 | 定位 | 说明 |
|---|---|---|
| H.263 | 早期视频会议 | 低码率、低复杂度 |
| H.264 / AVC | 应用最广 | 压缩率与复杂度平衡，I/P/B 帧、CABAC，兼容性最好 |
| H.265 / HEVC | 4K / 8K | 同画质码率约比 H.264 低 **50%**，专利与算力成本更高 |

## 三、色彩空间：RGB 与 YUV

- **RGB**：红、绿、蓝三通道，面向显示设备。
- **YUV**：**Y** 亮度 + **U/V** 色差。人眼对亮度敏感、对色度不敏感，因此可以对色度**降采样**（如 4:2:0），在不明显掉画质的前提下直接省掉一半以上的色度数据。
- 视频编码通常先转 YUV，再做 DCT 与量化。

| 分辨率档位 | 典型尺寸 |
|---|---|
| VCD | 352×240 |
| DVD | 720×480（NTSC）/ 720×576（PAL） |
| 720p | 1280×720 |
| 1080p | 1920×1080 |

## 四、3D 效果

- 原理：左右眼看到**略微错位**的两幅图，大脑融合后产生立体感。
- 裸眼 3D、3D 眼镜、VR 头显都是这个思路的不同实现。
- 在编码里，3D 视频需要额外传输**视差信息**，或采用多视角编码（如 MVC），码率约为单视角的 1.5~2 倍。

## 总结

| 层级 | 关键机制 | 一句话 |
|---|---|---|
| 图像 | DCT + 量化 + 熵编码 | JPEG 压的是**空间冗余** |
| 视频 | 帧内 + 帧间预测 | MPEG/H.26x 压的是**空间 + 时间冗余** |
| 色彩 | RGB → YUV + 色度降采样 | 利用人眼对亮度更敏感 |
| 3D | 左右眼视差 | 多传一路视差或多视角 |

> **一句话记忆**：JPEG 是空间上的压缩，MPEG/H.26x 是空间 + 时间上的压缩。
