# Keil/ARM 构建知识体系 · 边界与确定性层级

> **本文定位**
> 本文不新增构建机制，而是说明这套知识**如何被切分、每条结论的确定性处于什么层级、适用范围到哪里**。
> 目的是区分两个不同的命题：「在划定范围内闭环、自洽、无遗漏」与「整个客观知识域已被穷尽」。前者可验证，后者不成立。

## 1. 内容范围边界：主题归属

这是最先划定的边界，回答「一个主题放进哪一篇」。

### 1.1 构建文档的边界 = 构建主线 + 10 个进阶专题

| 类别 | 内容 |
|---|---|
| 构建主线 | 源码 → 预处理 → 编译 → ELF `.o` → `armar`/`armlink` → `fromelf` → 启动 CRT |
| 进阶专题（10 个） | `6.7` 自定义段与绝对定位；`8.8` Scatter 高级；`8.9` 静态栈分析；`10.11` printf 重定向与半主机；`10.12` 堆管理；`14.4` 浮点 ABI；`14.5` AAPCS 整数调用约定；`14.6` 内联汇编；`14.7` C11 原子与独占访问；`14.8` 编译器内置函数 |

> 构建文档第 `0.5` 节列的是其中五条（时间 / 层次 / 可判定性 / 平台 / 证据），不含「内容范围」；本篇把「范围」作为第 6 条补上，形成完整六边界。

### 1.2 相邻专题的边界 = 10 个相邻主题（第 6–15 节，均已升级为正式版）

调试硬件与 trace、HardFault 定位、Bootloader/IAP/OTA/安全启动、CMSIS 与 Pack、命令行与 CI、静态分析与规范、测试与覆盖率、存储与内存映射细节、复位与低功耗、独立学科层。**10 项均已写成正式版笔记**；大纲转为「索引 + 待扩展清单」，用于登记后续深化方向。

### 1.3 边界可由所有者主动移动

把某个相邻主题（如 HardFault）写成正式版，属于主动扩大构建文档边界，不构成当前文档的缺失。

## 2. 时间边界：构建期与运行期

回答「一个事实在什么时间点被确定」。

| 一侧 | 确定的内容 |
|---|---|
| 构建期（build time） | 段的大小、绝对地址、重定位、静态内存布局、内联与优化决策、符号解析结果 |
| 运行期（run time） | `__scatterload` 拷贝 RW、ZI 清零、栈与堆的动态分配、虚基类偏移的**使用**、异常与中断响应、依赖外部输入的分支 |

跨边界机制：

- **重定位**：构建期计算并回填地址，运行期由指令实际使用。
- **静态分析**：构建期对运行期行为做预测，预测受第 4 节的可判定性限制。

判据：一个问题若能在构建期解决，就不应留到运行期；若本质依赖运行期状态，则构建期只能建立占位与约束。

## 3. 抽象层次边界：层与层之间是契约接口

| 层 | 处理对象 | 与相邻层的接口/契约 |
|---|---|---|
| 应用层 | C/C++ 源程序 | 语言规范 |
| 编译器层 | 前端、IR、优化、后端 | 编译选项、目标架构声明 |
| 调用约定层 | 寄存器使用、参数传递 | AAPCS / AAPCS-VFP |
| 目标文件层 | ELF、段、符号、重定位 | ELF 格式规范 |
| 构建编排（横切） | 依赖、工具调用、链接、转换 | 工程文件、命令行契约 |
| 指令集层 | ARM/Thumb 机器码、寄存器 | ISA 规范 |
| 微架构层 | 流水线、FPU、MPU、NVIC | 架构编程模型 |
| SoC/硬件层 | Flash/RAM、总线、外设、电气 | 内存映射、外设规范 |

> 「构建编排」严格说不是与 ELF/ISA 并列的一层，而是**横跨多层的调度**；把它列入表中，是为了说明「工程配置 + 命令行」这一契约面。

使用原则：定位故障先确定所处层，再在该层内分析；不把上层语义错误（如类型不匹配）与下层硬件故障（如总线错误）混为一谈。层间契约（ABI、ISA、ELF、内存映射）是跨层协作唯一的稳定依据。

## 4. 可判定性边界：确定性的客观极限

### 4.1 三档确定性

| 档位 | 含义 | 示例 |
|---|---|---|
| 可静态确定 | 构建期可完全钉死 | 直线代码、固定地址、对象大小 |
| 已知不确定 | 随版本/配置变化，文中以限定语标注 | `--callgraph` 的输出格式、Call Graph 菜单位置、AC5 小写 intrinsic 集合、非 lock-free 类型支持 |
| 原理上不可完全判定 | 不存在能在有限时间内对所有输入给出确定答案的通用方法 | 函数指针实际目标、递归深度、动态分配大小、依赖运行时输入的路径 |

### 4.2 理论根源

第三档对应可计算性中的**不可判定性**：停机问题（给定程序与输入，判断是否终止）不可判定；更一般地，**Rice 定理**指出任何**非平凡的语义性质**都不可判定——「这个函数指针可能指向谁」「最大栈深是多少」「这条分支可达吗」都属于此类。停机问题只是其中一个特例。

**适用前提**：Rice 定理覆盖的是**语义/外延性质**（程序行为、计算结果），不包括**纯语法性质**（如括号是否匹配、标识符是否声明）。语法性质可判定，这正是编译器能可靠完成词法、语法与部分类型检查的原因——不可判定性并没有蔓延到“程序的一切性质”。

因此静态栈分析的四类局限（函数指针、递归、纯汇编、预编译库）不是工具不足，而是理论边界。

### 4.3 工程缓解

以约束替代通用判定：禁止或限制递归、收敛函数指针目标、对汇编与库单独人工核对、运行期用栈水位（如 0xCD 填充）测量实际占用。缓解只能缩小不确定区间，不能消除该边界。

## 5. 平台与工具链边界：结论的适用前提

| 边界 | 划分 | 实际影响 |
|---|---|---|
| 架构边界 | ARMv6-M（M0/M0+/M1）、ARMv7-M（M3）、ARMv7E-M（M4/M7）、ARMv8-M（M23/M33）、ARMv8.1-M（M55/M85） | 可用指令、DSP、FPU、TrustZone、Helium 支持不同 |
| 工具链边界 | AC5/AC6 与 GCC、IAR | ABI、对象格式、内联汇编语法互通有限，混链受 build attributes 约束 |
| 器件/厂商边界 | 具体芯片与厂商 | 内存映射、外设、中断号、选项字节不同 |

任何结论都带适用前提；跨架构、跨工具链、跨器件迁移时，前提必须重新验证，不能直接外推。

## 6. 安全边界与证据强度边界

### 6.1 安全边界（TrustZone-M）

由 SAU/IDAU 硬件强制划分安全态与非安全态；安全固件负责密钥与签名校验，非安全固件不能越权访问。该边界由硬件执行，不依赖软件自律。

### 6.2 证据强度分层

- 确定事实：可由规范、文件内容或实测直接验证。
- 限定结论：以「部分版本/视配置」标注，不写死。
- 待核实：仅列入 checklist，不进入正文结论。

### 6.3 完成度分层

定稿（构建文档）与大纲（相邻专题）严格区分，避免把「清单存在」误读为「内容已完成」。

## 7. 综合应用：给任意一条知识定位

对一条结论，依次回答三个问题：

1. **范围**：属于构建文档还是相邻专题？
2. **时间**：构建期可确定，还是运行期才确定？
3. **确定性**：可静态确定、已知不确定，还是原理上不可完全判定？

再标注其平台适用前提（架构/工具链/器件）。这四个坐标共同确定一条知识的位置，缺一不可。

### 示例

| 知识条目 | 范围 | 时间 | 确定性 | 平台前提 |
|---|---|---|---|---|
| 函数最终绝对地址 | 构建文档 | 构建期 | 可静态确定 | 受 Scatter 约束 |
| 虚基类子对象偏移 | 构建文档 | 偏移静态存于 vtable，调整加法在运行期 | 机制确定、具体值依对象 | 仅 C++、Itanium ABI |
| 含递归的最深栈用量 | 构建文档（8.9） | 构建期预测、运行期实测 | 原理上不可完全判定 | 受静态分析局限 |
| 半主机调用是否可用 | 构建文档（10.11） | 运行期 | 随库/探针配置 | 依赖调试器与库配置 |

## 8. 结论

- 「边界内完整」指：在所有者划定的范围、时间、可判定性与平台前提内，内容闭环且自洽；它不是「客观知识穷尽」。
- 六类边界分别回答：主题归哪篇（范围）、何时确定（时间）、处在哪层（层次）、能否确定（可判定性）、在何前提下成立（平台）、可信度多高（安全/证据）。
- 边界由所有者定义并可主动调整；边界外的内容以大纲形式沉淀，不被当作缺失，也不被伪装成完成。
